- `app/patients/[patientId]/page.tsx`: `params` typed as `Promise<{ patientId: string }>` and unwrapped with React's `use()` ,  Next.js 16 resolves route params as a promise (see `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/page.md`), whereas spec §13's `PageProps` shows it synchronous, predating that change.
- `lib/api/steps.ts` `listStepDefinitions()`: hits `GET /api/steps` (non-patient-scoped) instead of the `GET /api/patients/{pid}/steps` row in spec §14, to match the parameterless signature `listStepDefinitions(): Promise<StepDefinition[]>` given in spec §11. Needs confirming against the real backend route once it exists.
- `lib/constants/steps.ts`: added an additive `STEP_DEFINITIONS` (+ `getStepDefinition`) export beyond spec §10's listed exports ,  a local, offline copy of the eleven steps' explanatory content (from `docs/PROJECT_PLAN.md` §6) used as a fallback in `useStepStore.fetchDefinitions()` when the backend is unreachable, which is the normal case during frontend-only development.
- Fonts: used `@fontsource/ibm-plex-sans` / `@fontsource/ibm-plex-mono` (already a dependency, no network needed) instead of `next/font/google`, since this machine has no reliable access to fetch Google Fonts at build time and CLAUDE.md forbids large/network-dependent downloads. Weight 450 (spec's `--text-ui`) isn't shipped by the font package; using weight 500 there is the nearest available fallback in `tailwind.config.ts`'s `fontSize.ui`.
- Tailwind v4 is CSS-first; `tailwind.config.ts` is wired in via `@config` in `globals.css` to keep the binding token file spec asks for (§Appendix C.8) rather than moving everything into `@theme`.
